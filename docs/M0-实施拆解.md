## 0.3 umya 回写 Spike —— [~] 关键发现，策略需调整
Spike 例程：`engine/examples/spike_writeback.rs`（打开→写格→另存→读回 + 内容保留校验）。

**Spike 通过项**
- [x] 用真实模板跑通"打开→两个 sheet 写 AD3→另存→读回一致"（机械链路 OK）
- [x] 发现 umya **2.3.3** 无法打开含筛选定义名（`_xlnm._FilterDatabase`, localSheetId=0）的 绩效.xlsx
      → 升级 **3.1.0** 解决该问题
- [x] `target/spike-绩效.xlsx` 在 WPS 打开无"修复"提示（但你指出内容为空——见下）

**Spike 失败项（重要）**
- [ ] ❌ **umya 3.1.0 对 corpus 中 2/10 文件“静默读 0 格”**：
      `绩效.xlsx`（原 87/27 行）与 `补课时.xlsx` 读出的单元格数为 0，
      于是"另存"会生成**只剩所写那一格**的空表——这比报错更危险（静默丢数据）。
- [ ] 尝试 `workbook.xml.rels` 绝对 Target 归一化（`Target="/xl/..."` → 相对）后仍为 0 格，
      根因尚未定位（区别于其余 8 个可读文件的具体特征待隔离）。

**结论与决策（写引擎前必须先定）**
1. **模板"读整簿 + 全量重写"的回写路线在 umya 上不可信**（对 corpus 即 20% 静默失败）；
2. 转向设计稿 3.6/3.8 预留的备胎：**模板回写 = "读定位 + 最小 XML patch"**：
   - 定位行/表头：需要可靠 reader（评估 calamine 或自读 sheetXML + sharedStrings）；
   - 写：直接用 `zip` 重写目标 worksheet XML 的对应 `<c>` 单元格，**其余部件原样保留**；
   - 好处：不整簿重写 → 不依赖写库保格式能力；逐格 diff 好做（M1 已有对拍基线）。
3. umya 仍可用于：能正确读取的文件（8/10）作数据读取、以及"生成新文件"（如 补课时.xlsx 输出）场景。
4. 读取组件选用需新增一个快速 Spike（读 绩效/补课时 是否可达）后定稿。
